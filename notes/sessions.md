3. **Fixed: hover tooltip wasn't showing (and a venv mistake along the way).** Neel reported the new highlighting displayed correctly but hovering showed no tooltip at all. Root cause: the tooltip relied only on the browser's native `title` attribute, which doesn't reliably fire once the HTML is embedded inside a host page's own DOM (a marimo cell's output area) rather than opened as a bare page -- exactly this symptom. Fixed by drawing the tooltip with pure CSS instead (`ag-rel-tip` class + `data-tooltip` attribute + `.ag-rel-tip:hover::after { content: attr(data-tooltip); ... }`), still zero JavaScript; `title` is kept too as a harmless fallback. Verified visually with a headless-Chromium screenshot (hovering a real token from a real saved analysis correctly pops the tooltip) and one new unit test (suite now 1848 passed). Separately, while diagnosing this, realized the `.venv` this session had rebuilt earlier for its own test verification was built through the remote-device bridge's own sandboxed Linux VM, not Neel's real shell -- its Python interpreter was a symlink into that ephemeral session's own path, unusable from Neel's actual Terminal ("activates fine, but can't find marimo" was really "can't find anything, the interpreter itself doesn't resolve there"). Deleted that broken `.venv` and, for this round's verification, used a scratch venv built entirely outside the project folder instead. Added a warning about this exact gotcha to `notes/venv_setup.md` so it isn't repeated.

4. **Typography pass on the relationship-highlighting display.** Neel iterated on the highlighting design in a series of throwaway HTML mockups outside the repo (a "turn off background color on non-selected nodes when a relationship value is picked" idea, deferred at first -- see item 5) and, separately, liked two things about those mockups compared to the live notebook: a font size a bit larger than the surrounding text, and noticeably more line-height, both of which he said "greatly improve legibility, especially on hover." 5. **Neutralize non-selected tokens' colors.** Same-day follow-up once Neel clarified the typography pass alone wasn't what he meant -- he wanted non-participating tokens to actually go neutral gray when a relationship value is picked. Implemented in `tokengraph_to_relationship_html()`: a colored token gets flattened to a new neutral gray (`_NEUTRAL_FILL`/`_NEUTRAL_TEXT`, outside the verbal-unit palette) whenever a `relationship` is selected and that token isn't one of ITS OWN edges' start/end tokens -- computed per-token, so a direct object sitting in the same clause as a highlighted subject still goes neutral; only the matching edges' endpoints stay lit. This drives off the notebook's existing relationship dropdown, no new UI, as discussed. One deliberate refinement: selecting a relationship the sentence doesn't attest at all still behaves as the documented no-op (byte-identical to `relationship=None`) rather than flattening everything to gray, since neutralizing is gated on actually having a match. Added 3 new tests (a new two-clause fixture with real `verbalunitid`s, since the existing `_ARMA_VIRUMQUE_CANO` fixture turns out to never get any color at all). Full suite: 1851 passed (1848 + these 3), 2 skipped, 7 deselected -- unchanged otherwise, same scratch-venv convention. Regenerated `Claude outputs/rel_typography_check.html` with a genuine before/after (nothing selected vs. "subject" selected) so Neel can see it directly.
